## Known defects this run does NOT fix
Recorded so the figure is not over-read. All were measured this session.

1. **The random control omits 65 tensors.** `generate_random_mask.py:60` has
   `if param.dim() != 2: continue`, so all 64 layer-norms plus `model.norm` are
   absent from the mask. `apply_mask` skips parameters not present in the mask
   dict, so the Random condition keeps every layer-norm fully intact while
   Oracle/Magnitude have theirs reduced. Measured consequence: `feature_std`
   1.316e-03 for Random vs 9.255e-07 for Oracle — a factor of 1400 in
   activation scale between the two conditions being compared.
2. **The jitter is not a neutral perturbation.** Per-tensor `eps = std_i * 1e-3`
   under a global top-k transfers mask budget from low-variance tensors to
   high-variance ones. Measured: 0/291 tensors at the keep floor in the
   unjittered oracle vs 59/291 in the jittered one, the same 59 in every seed
   (agreement 1.000), with per-tensor budget-shift correlation 0.9988–0.9999
   across seeds. This is a deterministic bias, not tie-breaking noise.
3. **`zero_out` is destructive.** It zeroes 97.5% of every tensor including the
   base model, so all masked panels measure how much signal survives a
   lobotomy, not where the DPO update localises. `delta_only` /
   `anti_delta_only` are the sufficiency / necessity operators and were not run.
4. **Oracle and Magnitude-200 are the same mask.** Pairwise Jaccard on the
   unjittered set: Mag-200↔Oracle 0.998, Mag-100↔Oracle 0.963, Mag-50↔Oracle
   0.810. Their agreement in the figure is not independent corroboration.

## Follow-ups
- The clean, probe-free result worth reporting instead: the magnitude mask at
  step 100–200 recovers 96–99.8% of the full 500-step checkpoint-difference
  subnetwork.
- If the jitter study is to be kept, `eps` must be scaled by a global score
  statistic, or the jitter must run inside a `local_pool=True` per-tensor pool
  so noise cannot move budget across tensors.
